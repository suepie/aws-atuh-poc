## 結論（v3）

**判断は 3 つの論点に集約されました** — ①**顧客 IdP が 1,000 に収まるか** ②**DR を海外リージョンに置けるか（法務）** ③**MFA を TOTP 以外にできるか**。

| 判定 | 件数 | 内容 |
|---|:-:|---|
| 🔴 代替不能 / 重大 | **3** | **接続 IdP 数の天井 1,000**（P-16）/ **DR 先に大阪が選べない**（P-15）/ **TOTP MFA が DR 中に使えない** |
| 🟠 要件かアーキの変更が必要 | 4 | ES256 / 属性スキーマ不可逆 / セッション制御 / `sub` の形式 |
| 🟢 解消 | 1 | SAML IdP 不可 → ServiceNow の OIDC 化で回避可 |
| 🟡 自作で埋まる（Keycloak でも自作する） | 4 | SCIM 受信 / HRD / JIT 制御 / 管理 API |
| 🟢 Cognito の方が容易 | 4 | パスワード API / ブローカー分離が不要 / 運用負荷 / 構築工数 |

### 🔴 その 1: 接続 IdP 数の天井 1,000

**Identity providers per user pool = 既定 300 / 申請上限 1,000。** P-16 は「1000 **超**想定」なので初日から天井に張り付きます。回避にはプール分割が必要で、その場合 P-06（L2 単一 Realm）と P-19（issuer 単一）が崩れます。

**🔴 その 2・その 3 は DR 由来**（下記「DR」節）。

### v2 で解消した 🔴（初版から変更）

初版で「代替不能」としていた **SAML IdP 不可**は、次の 2 点により **🟢 解消**に変更しました。

1. 本基盤が SAML IdP として提供する相手は **ServiceNow 1 本のみ**（api-provision-matrix と U10 の `CL-SN-01` で確認）
2. **ServiceNow の OIDC SSO が自動ユーザープロビジョニング（JIT）を公式にサポート**（ServiceNow 公式ドキュメントに `Automatically provision users` 等のフィールドが存在）

ただし移行では 3 点が変わります — **PII 送出を userinfo 経由に確定**（P-10 との衝突回避）/ 突合キーの再設計 / Token Exchange 不可（Phase 1 対象外のため当面は影響なし）。

### DR（2026-09-16 追加調査）

**手段は 2026-06 に登場しました**（Multi-Region Replication）。**RTO は分オーダー**で、現行 Keycloak 設計の **RTO ≈ 14 日**より桁違いに良い一方、3 つの壁があります。

| 壁 | 内容 |
|---|---|
| 🔴 **大阪が非対応** | 対応は東京・ソウル・シンガポール・シドニー・ムンバイ等。**DR 先が海外になり APPI 越境移転（法 28 条）が新規発生**。現行の「データは国内」前提が崩れる |
| 🔴 **TOTP MFA がセカンダリで不可** | MFA 設定済みユーザーは**フェイルオーバー中ログイン不可**。管理者ほど締め出される |
| 🟠 **新規ユーザーが DR 中に入れない** | フェデレーションユーザーは「プライマリでログイン実績あり」が条件。JIT と正面衝突 |

詳細は [02-dr-analysis.md](02-dr-analysis.md)。

### コスト

初回リリース規模（100〜500 万 MAU）では **Cognito の方が安い**（Cognito Essentials $180K/年 vs Keycloak インフラ $122K/年 + 構築 545〜1,026 人日）。500 万を超えると逆転し、10M では ADR-032 の 14 倍差が再現されます。

**DR（MRR）を入れると +$54K〜540K/年**が上乗せされ、100 万 MAU で $234K/年。ただし **P-05 は 2026-08-16 に再検討中へ差し戻され、現行のコールド DR 方針と顧客希望値（RTO 1 日）が両立していない**ことが既に認識されています。DR 要件が確定すると **Keycloak 側のコストも上がる**ため、この比較は「Cognito にだけ DR コストが乗る」話ではありません。

## 次にやること

**🔴 3 件に対応する確認が 3 つあります。**

| # | 確認事項 | 効果 |
|---|---|---|
| **U-6** | **ブランドあたりの顧客 IdP 実数** | 1,000 未満に収まるなら 🔴 が 1 件減る。P-19 で Phase 1 = 1 ブランドなので**そのブランドの顧客 IdP 数**が分かれば判定できる |
| **U-13** | **海外リージョンに DR を置けるか（法務判断）** | 🔴 の 1 件が動く。法 28 条の根拠（規則 16 条体制整備 / 本人同意）を立てられるか |
| **U-8** | **Passkey / WebAuthn はセカンダリで動くか** | 動くなら **TOTP MFA の壁**を回避できる |
| U-5 | ES256 は規制要件か設計選好か | 後者なら 🟠 が 1 件減る |

**U-6 / U-13 / U-8 が全部クリアできれば、判断はコストと 🟠 群のトレードオフになります。** 逆にどれか 1 つでも NG なら、そこで結論が出ます。
