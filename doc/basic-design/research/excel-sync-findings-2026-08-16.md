## 1. 【最重要】ID の名前空間が衝突している

同じ文字列が**2 つの別物**を指しています。Excel が ID をキーにしている場合、行が混ざります。

| ID | グループ A（hearing-checklist） | グループ D（00a のタスク） |
|---|---|---|
| `A-2` | 想定 MAU 規模（3 年後）— 未回答 | G-SPI-Compat 実測（10 人日）— 実質残ブロッカー |
| `A-4` | 顧客拠点の地理分布 — 未回答 | G-LDAP（**2026-07-30 廃止**） |
| `A-7` | 新規顧客追加の頻度 — 未回答 | G-OSAKA 在庫確認（3 人日） |

衝突は `A-*` だけではありません。**`B-1〜B-5` / `C-1〜C-8` / `D-1〜D-18` / `E-1〜E-8` / `F-1〜F-4` / `G-1〜G-4` はすべて 00a のタスク ID** ですが、hearing-checklist にも `B-200` `C-201` `G-SCIM` などの同じ接頭辞が存在します。数字部分で辛うじて分かれているだけで、設計上の保証はありません。

**依頼事項（Excel 側）**: TSV では `A-2【hearing】` / `A-2【00a タスク】` のように出自を付けて一意化しました。Excel でも**出自列を独立させる**か、タスク ID に `T-` 接頭辞を付けて恒久分離してください。

## 3. 【重要】要件表と基本設計が正面から矛盾している 2 件

**禁則 K-1**（U9 §9.5）は「realm 全体の export / import / partial-export を**一切使用しない**（バックアップ・監査を含む全用途）」と定めています。理由は、1000 IdP 環境では realm 定義が 30MB 級になり運用として成立しないため（keycloak#14851、U2 §2.7.4）。

ところが要件表は次のように書いています。

| 要件 | 要件表の記述 | 禁則 K-1 との関係 |
|---|---|---|
| `FR-USER-009` バルクインポート | 「✅ Realm Import」 | **禁止されている手段を可としている** |
| `NFR-MIG-004` データエクスポート | 「✅ Realm Export」 | **同上** |

どちらも「できる」と書かれたまま実現手段が存在しません。**代替経路（SCIM 受信 / JIT 任せ / 自作の一括投入 API / Admin API の単位取得）の選択が未決**です。

## 5. 要件 ID と基本設計のトレーサビリティが切れている

グループ A の 25 件を `doc/basic-design/` + `doc/adr/` で ID 検索したところ、**言及があったのは 4 件のみ**（FR-INT-002 / NFR-PERF-004 / B-TENANT-ISO-1 / FR-AUTH-007）。残る 21 件は要件 ID がどこにも現れません。

決定そのものは存在します（例: `NFR-DR-001` の答えは `P-05`、`NFR-SEC-017` の答えは `D-U6-11` + `D-U7-14`）。**設計書が独自の決定 ID（`D-Ux-nn`）だけで書かれていて、要件 ID を引いていない**のが原因です。

このため、**Excel で「要件 → 設計」を自動で追えません**。今回の TSV では題材ベースで人手照合して紐づけました。恒久対策としては、要件表側に「対応する設計決定」列を設けるのが最も安価です（設計書 10 冊に手を入れるより影響が小さい）。

## 6. 工数の整合性 — 二重計上は 1 件も見つからず、ただしルール文が矛盾

3 つの枠は**スコープが異なり重複していません**。

| 枠 | 人日 | スコープ |
|---|---:|---|
| ① 基本設計クローズ（00a §1-4） | 244 | 調査 97 + 検討 147 |

| ④ テスト（gap-audit §10） | 363 | 結合〜UAT |

同じ題材が複数の枠に出るのは**工程が違うため正常**です。例: `D-6`（メール送信設計 3 人日）は①、`DU-U6-12`（SES 基盤 6 人日）は②③。二重計上ではありません。TSV の該当行にその旨を注記しました。

ただし **gap-audit 内部でルール文が矛盾**しています。

- §9 の分割ルール: 「**PoC ゲート（①に含む 87）と重複する分は二重計上しない**」
- §10 のスコープ宣言: 「**PoC 重複 = フル再計上**（負荷 / DR / セキュリティを本番前に満額実施）」

**§10 が新しく（2026-08-12 ユーザー確定、200→363 への上方修正）、こちらが正**です。§9 の一文が更新から取り残されています。Excel の人日 3 列化に §9 のルールをそのまま使うと 363 と食い違うため、**§9 の該当文を削除するか §10 に合わせて書き換える**必要があります。

もう 1 点、**00a 内で総計の表記が割れています**。§1 の表は **244**（97+147 で算術的に正しい）、§6 の本文は 2 か所とも **242**（v1.1 時点の値が残存）。244 が正です。
