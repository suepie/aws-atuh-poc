## 2. 体裁

既存シートと揃える。

1. **ヘッダ行を 1 行目**に置き、他シートのヘッダと同じ書式（背景色・太字・中央揃え・固定）にする
2. **ウィンドウ枠の固定**: 1 行目とA〜D列を固定（横に長い表なので、機能名を見ながら右へスクロールできるように）
3. **オートフィルタ**を A1:J109 に設定
4. **列幅**: A 8 / B 12 / C 22 / D 26 / E 28 / F 46 / G 16 / H 16 / I 18 / J 60。**J 列だけ折り返しを有効**にし、行の高さは自動
5. **F 列（エンドポイント）は等幅フォント**（Consolas 等）。パスの読み違いを防ぐため
6. **A 列（対象）で色分け**: Broker と IdP で薄い背景色を変える。または条件付き書式
7. **H 列・I 列に条件付き書式**（下表の色）。絵文字はそのまま残す

## 3. 集計（同じシートの右側、L 列以降に置く）

読む人が真っ先に知りたいのは「そのまま渡せるものと、作るもの」の量なので、小さい集計表を 3 つ置く。

**① 区分ごとの件数**（L1 から）

| 区分 | 件数 |
|---|---|
| ✅ 標準 | 30 |
| ⚠ 標準（制約） | 43 |
| ⚙ 設定のみ | 11 |
| 🔧 カスタム必要 | 22 |
| ⛔ 使わない（決定） | 1 |
| ❌ 不可 | 1 |
| **計** | **108** |

**② 対象 × 区分のクロス**（L10 から）: 行に 対象（Broker / IdP）、列に 区分。ピボットテーブルでもよい

**③ コストの内訳**（L20 から）: 🔺 標準外 16 件と 🔻 削減候補 6 件は、**それぞれの「提供する API」名を一覧で書き出す**（何にお金がかかり、何を削れるかが 1 画面で見えるようにするため）

- 🔺 16 件: 接続情報の自動追随 / 証明書期限の監視 / ログイン振り分け（HRD）/ アプリへの変更通知（Webhook）/ 長期未使用者の自動停止 / 保存期限切れの消去 / 実在推測の防止 / パスワードの照合 / 流出パスワードの使用拒否 / メールを持たない人の復旧 / 振り分け失敗時の切替 / 管理 API の内部公開 / 不正兆候の検知 / 登録経路の区分判定 / 最終ログイン日時の取得 / パスワードの変更日・期限の取得
- 🔻 6 件: ユーザ登録の受信（SCIM）/ ユーザ更新の受信（SCIM）/ 削除通知の受信（SCIM）/ ユーザ検索の受信（SCIM）/ パスワードの自己再設定 / 一括の有効化・無効化

## 5. 検収

1. 行数 108 / 列 10。ヘッダを含めて 109 行分のデータ
2. C 列（機能グループ）と D 列（機能名）の値が、すべて **機能名一覧シートに存在する**。**ただし 1 行だけ `—` がある**（「パスワードの取得」の行。対応する機能を持たないため）。この 1 行は正しい値なのでエラー扱いしない
3. B 列（機能ID）が機能名一覧に存在する。**同じ 1 行だけ `(なし)`**。これも正しい値
4. H 列・I 列の値が §1 の件数と一致する
5. F 列に改行が入っていない（1 セル 1 行）
6. 既存シートの行数・人日が**変わっていない**（このシートは追加のみ）
