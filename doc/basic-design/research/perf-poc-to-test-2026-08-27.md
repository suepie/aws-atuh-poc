# 性能実測を PoC（基本設計）→ テストへ移管

- **日付**: 2026-08-27
- **種別**: research note（クラスタ A と ④テストの再配置）
- **発端**: ユーザー指示「**PoC と実測について、性能に関わるところはテストに回してほしい**」
- **結論**: **可能。しかも移管すべき理由が 2 つある**（二重計上の解消／既決方針との整合）。

---

## 1. 移管すべき 2 つの理由

### 1-1. 二重計上になっていた

クラスタ A（基本設計 PoC）と ④テスト D 負荷（64 人日）が**同じ対象を 2 回測る**構成だった:

| 基本設計 A（PoC） | ④テスト D 負荷 | 重複 |
|---|---|---|
| A-1.2 認証実測（応答時間） | PT-01 認証負荷 | **重複** |
| A-1.3 管理操作の応答実測 | （PT-02 に該当項目なし） | 片方のみ |
| A-1.4 キャッシュ・メモリ実測 | PT-02 IdP スケール（キャッシュ含む） | **重複** |
| A-3.4 テナント数スケール | PT-03 SCIM/射影スケール | **重複** |
| A-3.5 バルク投入・流量 | PT-03（バルク 5 万件） | **重複** |
| A-3.6 参照用データ読取速度 | PT-03（読取 p99） | **重複** |
| A-8 パスワード処理の速度実測 | （PT-01 に明示なし） | 片方のみ |
| A-10.1/10.2 拡張機能の高負荷 | PT-05 高負荷耐久 | **重複** |
| A-1.1 試験環境・データ生成 | TE-01/TE-02 環境・データ生成基盤 | **重複** |

> これは「**PoC 重複＝フル再計上**」（2026-08-12 のユーザー確定）という方針で**意図的に 2 回計上**していたもの。今回の指示で**テスト側 1 回に集約**する。

### 1-2. 既決方針と整合する

**接続先スケールの実測は 2026-07-30 に「実測困難のため仮定値で設計継続、実測は後追い検証に格下げ」と決定済み**。設計フェーズのゲートではなくなっているため、**テストフェーズで測る方が本来の位置づけに合う**。

## 4. 受け入れるリスクと対策

**リスク**: 性能の実測が**テストフェーズまで遅れる**ため、**未達が判明したときの手戻りが大きい**（設計・構築の両方に及ぶ）。

**対策 1 — 分岐の増額**: 既存の CT-2「負荷試験で合格基準未達の場合 +12」を、**設計・構築への手戻りを含めて +25 に増額**する。

| 分岐 | 従前 | 是正後 |
|---|---|---:|
| CT-2 負荷試験の未達 | チューニング後の再実測 2 巡（+12） | **チューニング再実測 + 設計見直し + 実装手戻り（+25）** |
| | 条件付き合計 300 | **313** |

**対策 2 — 前倒しトリガーの明文化**: 次のいずれかに該当したら、**テストを待たず前倒しで実測**する（その場合は CT-2 から充当）:
- 顧客から接続先数・利用者数の確定値が出て、**仮定値を大きく超えた**とき
- 構築フェーズで**設計時の想定と異なる実装方式**を採らざるを得なくなったとき
- ④テストの開始が**リリース予定日から 3 ヶ月を切った**とき（是正の時間が確保できないため）
