# 【選択肢】最初のアプリが作り、基盤チームは運用を引き継ぐ

- **日付**: 2026-09-03
- **位置づけ**: 🔵 **採用予定ではない**。**工数をアプリチームへ寄せたい要望が出た場合の分担案**（[器のみ案](shell-only-analysis-2026-09-02.md)の具体形）
- **発端**: ユーザー整理「**最初のアプリが認証製品の上の仕組みを全部作り、あとのアプリはそれに合わせる。こちらは運用だけをする。管理画面もアプリが構築し、その後運用を引き継ぐ**」

---

## 1. モデル

| 時期 | 基盤チーム | 最初のアプリチーム | 2 つ目以降のアプリ |
|---|---|---|---|
| **構築期** | 器（設備・DB・ネットワーク）を用意 | 🔵 **認証製品の上の仕組みを全部作る**（振り分け・利用者管理・管理画面・権限） | — |
| **引き継ぎ期** | 🆕 **受け取って運用できる状態にする** | 引き渡す | — |
| **運用期** | 🔵 **運用する**（監視・障害対応・版の更新） | 自分のアプリを作る | 🔵 **既にあるものに合わせる** |

> **これは「受託して作ってもらい、あとで引き取る」形**である。**現実によくある**が、**引き継ぎの成否ですべてが決まる**。

## 4. 🔴 成立条件（これが揃わないと破綻する）

### 4-1. 🔴 最初のアプリが「自分のため」でなく「全体のため」に作るか

**最初のアプリチームには、自分の業務に最適化する動機しかない。**

| 起きること | 例 |
|---|---|
| 属性の持ち方が自分の業務前提になる | 社員番号を必須にしてしまい、**社外の利用者を扱えない** |
| ログイン処理が自分の要件に最適化される | **他アプリが必要とする分岐が入らない** |
| 管理画面が自分の運用前提になる | **他アプリの管理項目が無い** |

→ **対策**: 🔴 **基盤チームが設計レビューに入る**。**「あとのアプリが合わせられるか」を見る役**は誰かが持つ必要がある。
→ **これを外すと「共通基盤」ではなく「最初のアプリの付属品」になる**。

### 4-2. 🔴 引き継げる状態で渡されるか

**作った人がいなくなった後に運用できる必要がある。**

| 必要なもの | 無いとどうなるか |
|---|---|
| **設計書** | 🔴 **なぜそうなっているかが分からず、障害時に直せない** |
| **運用手順** | 何をどう直すかが分からない |
| **試験の記録** | 変更したとき何が壊れるか分からない |

→ 🔴 **アプリチームが設計書を書かないなら、引き継ぎ時に基盤チームが書き起こすことになり、工数が戻ってくる**。
→ **「設計書を書く」約束を、引き渡しの条件として先に決める**必要がある。

### 4-3. 🔴 「あとのアプリはそれに合わせる」が本当に成立するか

| 条件 | 判断 |
|---|---|
| **アプリ同士の業務が近い** | ✅ 成立しやすい |
| **利用者の種類が同じ**（社員なら社員だけ、顧客なら顧客だけ） | ✅ 成立しやすい |
| 🔴 **業務も利用者も違う**（社員向けと社外向けが混在） | ❌ **合わせられず、結局作り直しになる** |

→ **2 つ目以降が「合わせられない」と判明した時点で、この案の利点は消える**。

### 4-4. 責任分界

| 事象 | 誰の責任か |
|---|---|
| 設定の誤りで認証が素通り | 🔴 **作ったのはアプリ、運用は基盤 → 曖昧になる** |
| 引き継ぎ後の障害 | 基盤（運用者）だが、**原因は構築時の設計** |

→ **引き渡しの時点で「どこまで直っていれば受け取るか」を決めておく**必要がある。

---

## 5. 🔴 最大のリスク — **引き継いだ後に直せない**

| 段階 | リスク |
|---|---|
| 引き継ぎ直後 | 動いているので問題が見えない |
| **半年後** | 🔴 **変更依頼が来たとき、なぜそうなっているか分からず手が出ない** |
| **障害時** | 🔴 **設計意図が分からないまま復旧を試みることになる** |

**対策**: 引き継ぎ工数（約 60）に **「設計意図の聞き取りと文書化」** を必ず含める。**動くものを受け取るだけでは足りない**。

---

## 6. 判断

| | |
|---|---|
| **成立するか** | 🔺 **条件つきで成立する**（§4 の 4 点） |
| **削減** | **704 → 約 390（-45%）** |
| **2 つ目以降** | ✅ **1 アプリ 30 前後で済む**（器のみ案より優れる点） |
| **推奨** | 🔺 **顧客都合で工数を寄せる必要があるなら、器のみ案よりこちらが現実的** |
