### 1-1. 中核なのに最小構成から外れる 12 機能

| 機能名 | 行き先 | なぜ外せるのか |
|---|---|---|
| 使えるアプリの設定 / アプリ内の役割の設定 | アプリ分担 | **アプリが自前で持てば成立する**（基盤としては欠けるが、システム全体としては成立） |
| 権限情報の一括取得 / アプリ利用可否の判定 | アプリ分担 | 同上 |
| 参照用データの更新 | アプリ分担 | 権限を基盤が持たなければ**そもそも不要になる** |
| アプリへの変更通知 | アプリ分担 | **アプリが定期的に問い合わせる**方式で代替 |
| 接続先の自動振り分け | 別途切り出し | **顧客ごとに URL を分ける**方式で代替（§5-3） |
| 顧客システムからの利用者登録 / 更新 / 削除通知 | 別途切り出し | **初回ログイン時の自動登録のみで運用**（顧客側の変更は次回ログインで反映） |
| 業務システムへの認証提供 | 別途切り出し | 別プロジェクト |
| 不正兆候の検知 | 別途切り出し | 通常のシステム監視で代替 |

> **この 12 件が「最小構成の実体」**である。**外すと基盤の価値は確実に落ちる**が、**認証そのものは成立する**。逆に言えば、**残り 22 の中核は代替手段が無い**。
