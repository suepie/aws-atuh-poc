## 1. 指摘への対応

| 指摘 | 何が起きていたか | どう直したか |
|---|---|---|
| **「横断」という機能グループに違和感** | 161 行・331 人日が「横断」に入り、機能の話か非機能の話か区別できなかった | **「横断」を廃止**。非機能は **`非機能: ○○` の 9 グループ**に分け、機能に紐づくものは機能グループへ移した |
| **「ログイン処理全般」は「ログイン」にすべき。しかも誰のログインかで分けるべき** | ログインが 1 つの塊で、対象者が読み取れなかった | ログインを **4 グループ**に分けた（振り分け / フェデレーション / ローカル / 画面）。さらに例に挙がった「本番設定: 同時受付数の上限」は**ログイン機能ではなく非機能**だったので `非機能: 性能・拡張性` へ移した |
| **機能名が一意でない（「A／B」の連結）** | 23 種が連結名だった | **全廃**。1 行 = 1 機能名にした |
| **「権限管理側への引き渡し」というグループはおかしい。初回ログイン時の動きならグループはログイン** | データの流れ先でグループを付けていた | **グループを廃止**し、初回ログイン時に起きることは **`フェデレーションログイン`** に置いた。識別子の対応づけと参照用データの更新は `権限管理` に移した |
| **「初回ログイン者」ではなく「初回ログイン時」** | — | 「**初回ログイン時の権限側への識別子連携**」に改めた |
| **非機能は `非機能:` を付ける** | — | 9 グループすべてに接頭辞を付けた。**`非機能:` で絞れば非機能だけ抜ける** |

## 3. 分類の考え方（次に迷ったときの基準）

| 問い | 判断 |
|---|---|
| その行は**特定の機能について書いているか** | はい → 機能グループ。いいえ → `非機能: ○○` |
| ログインの行はどこへ | **誰のログインか**で決める。顧客 IdP 経由なら `フェデレーションログイン`、本基盤に直接収容している人なら `ローカルログイン（Keycloak-IdP 収容）`、どちらへ送るかを決める処理は `ログイン振り分け（HRD）` |
| **ログインをきっかけに起きること**（自動登録・属性更新・識別子の連携）はどこへ | **ログインのグループ**に置く。データの届け先（権限側）で分類しない |
| 顧客・アプリ向けの資料はどこへ | **その資料が説明している機能**のグループへ。特定の機能に紐づかない導入・参照部分だけ `非機能: 提供ドキュメント` |
| 担当が基盤とアプリで分かれる機能は分けるか | **分けない**。担当は担当列で表す。内容が違うときだけ分ける（例: `操作記録の照会`＝見る側 と `監査ログの取得・保管方式`＝残す側） |

## 4. 前回からの主な変更（要確認）

| # | 変更 | 理由 |
|---|---|---|
| 1 | 「ローカルユーザー管理」→ **「Keycloak-IdP 収容ユーザのログイン」** | ログイン機能なので、指示どおり「誰のログインか」で命名した |
| 2 | 「ブローカー側のシャドウユーザ作成（F-AUTH-07）」を **「初回ログイン時のユーザ自動作成（JIT）」（F-PROV-01）に統合** | 同じ出来事の 2 面。WBS 側でもすでに 1 行に吸収済み |
| 3 | 「ログイン後の属性取り込み_SCIM（F-AUTH-08）」を **「ログイン時の属性更新」（F-PROV-02）に統合** | 同じ処理。これは SCIM ではなく JIT の属性同期なので、名称の「_SCIM」は誤り |
| 4 | 「強制ログアウト（アプリ）／（ブローカー）」「顧客の作成（アプリ）／（ブローカー）」の**担当による 2 分を解消** | 担当は担当列で表せる。機能としては 1 つ |
| 5 | 「操作記録の照会（アプリ）／（ブローカー）」は **内容で 2 つに分けた**（照会する機能 と 取得・保管の方式） | 担当ではなく中身が違うため |
| 6 | 機能 ID を **6 つ新設**（F-AUTH-23〜28: セッション・ログアウト連携・ログイン画面・エラー画面 2 種・同意管理）、**F-AZ-10**（JWT 項目定義）、**F-ADM-23**（顧客の解約）、**F-ADM-24**（開示・削除請求）、**F-ADM-25**（監査ログの取得・保管）、**F-INT-13**（アプリの接続登録） | 「横断」に埋もれていた実体のある機能。設計書もテストも必要 |
| 7 | 非機能に **NF-ARC / NF-PRF / NF-AVL / NF-SEC / NF-OPS / NF-MIG / NF-STD / NF-MGT / NF-DOC** の ID を採番 | 機能 ID 列が空にならず、ピボットで扱える |
