## 2. 場合網羅マトリクス（テスト設計の直交軸）

E2E（区分 B）が覆うべき組合せを明示化し、各 ST 項目の内訳に反映する:

| 軸 | 値 | 主に効く項目 |
|---|---|---|
| **ユーザ種別** | P-1 基盤運用者(ローカル) / P-2 テナント管理者(フェデ) / P-3 フェデ従業員 / P-4 IdP なしテナント利用者(IdP-KC ローカル) | ST-01/02/06/07 |
| **プロビ経路** | jit / scim(D1) / scim(D2) / local-admin / portal / app | ST-03/04 |
| **テナント種別** | 顧客 IdP 保有(SAML) / 保有(OIDC) / 非保有(IdP-KC 収容) | ST-01/03、RI-01/02 |
| **識別子** | email 保有 / **email 非保有（`<tenant>-<userid>`）** | ST-02/08、ST-03 |
| **正常/異常** | 正常系 / **異常系（拒否・失効・タイムアウト・不整合）** / **障害注入** | 全 ST + **新規 AB-01** |
| **削除信号** | 能動（idm-api 削除・SCIM DELETE）/ **受動（顧客 IdP+JIT のみ = 信号なし）** | ST-04 |

> **重要**: 「〜の状態で〜の場合」の代表例＝**受動デプロビ**（顧客が IdP 側で無効化しても信号が来ない → フェデ自然失敗＋90 日バッチ）。現行 ST-04 はここを明示的に持っていない → 内訳に追加。
