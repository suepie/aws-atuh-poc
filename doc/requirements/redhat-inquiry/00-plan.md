# Red Hat 照会 — 計画と全体像

作成: 2026-08-18 / 目的: **ROSA / RHBK の検証残・公式文書が無いか曖昧な箇所・設計に関わる実現性**を、Red Hat 担当者との面談で確認しきる

---

## 0. なぜ今か

`ADR-056`（ROSA 採用）は **Accepted（条件付き）** で、**採用条件 4 点が未充足**のまま基本設計が進んでいる。加えて `G-DPA`（APPI 28 条）の残ブロッカーが **Red Hat SRE の越境閲覧** 1 点に絞られており、**ここが崩れると基盤構成そのものを再検討**することになる。

**面談は「条件付き」を外す機会**であり、設計全体から未確認事項を漏れなく持ち込む。

## 2. 優先度の考え方

| 優先度 | 意味 |
|---|---|
| **最優先** | **回答次第で基盤構成・契約・金額が変わる**。面談の場で必ず聞く |
| 通常 | 設計の詰めに必要。書面回答で足りる |
| 後回し可 | あると良いが、無くても設計は進む |

## 3. 面談の進め方（推奨）

**D 群（セキュリティ）を最初に置く。**`G-DPA` は**残ブロッカー 2 件のうちの 1 件**で、ここが崩れると他の質問が無意味になるため。

1. **D 群 最優先 3 問**（Approved Access / `oc logs` の監査追跡 / SRE 所在地の地理制限）
2. **A 群 最優先 3 問**（3 年契約見積 / cluster fee 割引 / サポート責任分界の書面化）
3. **B・C 群 最優先 4 問**（SPI 互換 / 大阪の在庫とクォータ ほか）
4. 残りは書面回答を依頼

**面談の場では最優先 12 問に絞る。**残 25 問は一覧を渡して書面回答を求める形が現実的。

## 5. Excel への展開方針

**単元ごとに 1 シート**（A〜F の 6 シート）とし、1 シートあたり 4〜8 問に抑える。列は次の 9 列。

| 列 | 内容 | 用途 |
|---|---|---|
| `RH番号` | `RH-A-01` 形式 | 一意キー |
| `単元` | A〜F | グルーピング |
| `優先度` | 最優先 / 通常 / 後回し可 | 面談で聞く順 |
| **`質問（先方提示用）`** | **平易な日本語。前提知識なしで読める** | **Red Hat に見せる列** |
| **`補足（先方提示用）`** | **背景と、どう答えてほしいか** | **同上** |
| `設計ID` | `ADR-056 残TBD③` `G-SPI-Compat` など | 設計との紐付け |
| `なぜ聞くか` | 社内向けの理由 | 先方には見せない |
| `回答が無いとどうなるか` | ブロックされる作業 | 社内の優先度判断 |
| `出典` | 設計書の該当箇所 | 追跡用 |

**先方に見せるのは `質問` と `補足` の 2 列のみ。**設計 ID や社内事情の列は非表示にして提示する。
