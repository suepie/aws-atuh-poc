## 将来の機能についての表記（2026-08-27 改訂）

**本資料では、Phase 1（第 1 期）で提供する範囲のみをお約束します。**

技術的な発展方向として想定しているものは資料中に記載していますが、**「いつ提供する」という時期のお約束はいたしません**。該当する箇所には **「提供時期は未定」** と明記しています。

| 表記 | 意味 |
|---|---|
| **Phase 1 / 第 1 期で提供** | **お約束の対象**です。契約に記載します |
| **Phase 1 では対象外・提供時期は未定** | 技術的な方向性としては想定していますが、**実施が確定しておらず、時期のお約束はいたしません** |

**この方針に変えた理由**は、次期以降の実施自体が未確定であるためです。実現できるか分からないものを時期つきでお約束すると、**果たせない約束**になります。**確実にお渡しできるものだけを契約に書く**方針といたしました。

必要な機能が「提供時期は未定」に該当する場合は、**その旨を早めにお知らせください**。ご要望の内容によっては Phase 1 の対象に含めるかを検討いたします。

## 読み方のお願い

- **「★現行」= 現在の設計での暫定値**です。各選択肢の表に必ず 1 つ記載しています。
- **設計書に書かれていないことは、推測で補っていません。**情報がない箇所は「**設計書に記載なし**」と明記しています。実測前の数値は「見積もり」「実測待ち」と正直に記載しています。
- 専門用語は日常語に置き換えています（例: 通行証＝ログイン後にアプリへ渡す電子的な身分証／端末に保存する鍵＝パスキー／追加の本人確認＝多要素認証）。

## 特にご判断が重い項目（先に読んでいただきたい 6 件）

| 項目 | なぜ重いか |
|---|---|
| **P-18**（④）| **インターネットの出入口を他組織が管理する**という前提。攻撃対策の一部が「要求仕様として出す」形になり、本資料の複数項目に波及します |
| **NFR-COMP-001**（⑤）| 海外からの保守アクセスをどこまで許容するか。**基盤の形（3 段階の選択肢）と公表文書**が決まりません |
| **NFR-OPS-009**（⑥）| サポート体制。**リリース時点では規制業種のお客様を受け入れられない**という制約に直結します |
| **NFR-OPS-003 / FR-ADMIN-007**（⑥②）| 記録の保存年数。**改ざんできない保管は後から短くできません**（構築前が最終決定タイミング） |
| **B-RTBF-1**（⑤）| 削除請求と記録保持の境界。**稼働後の遡及ができません** |
| **B-TESTDATA-1**（⑤）| 検証環境に本番データを入れるか。**一度入れると取り消せません** |

## 「後から変えにくい」項目の一覧

以下は、**運用開始前に決めておく必要がある**ものです。

| 項目 | 理由 |
|---|---|
| 記録の保存年数（短縮方向） | 改ざん不能な保管は削除できない |
| 検証環境への本番データ投入 | 一度投入すると「なかったこと」にできない |
| 削除請求と記録保持の境界 | 稼働後に境界を変えても、既に保管領域に入った記録には遡及できない |
| ネットワークの住所範囲 | 構築後に変更不可 |
| 1000 社を 1 環境に収容する前提の必須対策 7 点 | 特に「ログイン画面に接続先一覧を出さない」は利用者体験に直結し、後から変えにくい |
| 24 時間対応の約束 | 一度約束するとサポート水準の縮退は実質不可 |
