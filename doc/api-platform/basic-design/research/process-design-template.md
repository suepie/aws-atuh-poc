# 処理設計書（Excel）雛形の定義 — シート構成と処理分解カタログ

作成: 2026-09-10。**本書が雛形と処理分解の SSOT**。Excel 実体は `doc/excel/apipf-process-design.xlsx`（生成スクリプト: `tools/build_process_design_template.py`）。
対象: 認証実装確認処理（外形監視）。設計の正は 10-18 章。本書は「それを処理単位に分解し、Excel に書き込める形にした器」。

---

## 1. なぜ処理単位に分解するか

10-18 章は**領域ごと**（構成・実行モード・検知・台帳・IAM…）に書かれており、レビューと合意には適するが、**実装・単体テスト・運用手順の起点にはならない**。そこで「1 つのトリガから 1 つの結果までの最小単位」＝**処理**に割り、処理ごとに I/O・手順・例外・権限を確定する。この粒度が WBS の `-d`（設計）成果物と 1:1 対応する。

## 2. Excel シート構成

### 2.1 共通シート（8 枚）

| # | シート | 内容 |
|---|---|---|
| 00 | 表紙・改訂履歴 | 名称・版・作成/承認・改訂履歴・参照 md のコミット時点 |
| 01 | 本書の位置づけ・前提 | 目的 / 読者 / 上位設計との関係 / 前提条件（BD-P・P-xx）/ 用語 |
| 02 | 全体構成 | アカウント構成・リソース一覧・通信経路（10 §10.1.5-10.1.6 の写し）|
| 03 | **処理一覧** | 本書のハブ。P-xx の一覧＋各処理シートへのリンク |
| 04 | 共通仕様 | 全処理に共通する規約（命名・ログ・エラー処理・リトライ・冪等・タイムアウト・環境変数・タグ）|
| 05 | データ定義 | 台帳スキーマ / 監視資材 / イベント payload / メトリクス |
| 06 | IAM・権限一覧 | ロール × 権限 × 利用処理のマトリクス |
| 07 | 非機能 | 性能・上限・コスト・監視/アラーム・保持期間 |

### 2.2 処理シート（P-xx、32 枚）

**全処理で同一レイアウト**とする（レビュー時の見落とし防止・テンプレ流用のため）。

| 節 | 項目 | 記載内容 |
|---|---|---|
| — | 処理 ID / 処理名 | タイトル行 |
| 0 | 概要 | 1〜2 行で「何をする処理か」 |
| 1 | 基本情報 | 区分 / フロー内の位置 / 起動元 / 起動先 / 呼び出し方式（同期・非同期・内部）/ 実行主体 / 頻度・タイミング / 前提条件 |
| 2 | 入力（I）| 項目・型・必須・取得元・説明/例 |
| 3 | 出力（O）| 項目・型・出力先・説明/例 |
| 4 | 処理手順 | 番号付きステップ・補足/参照 |
| 5 | シーケンス | 矢印記法のテキスト（必要なら図を貼付）|
| 6 | 例外・異常系 | ケース / 検知方法 / 動作 / 通知 |
| 7 | 冪等性・リトライ | 再実行時の振る舞い・状態更新のタイミング |
| 8 | 権限・エンドポイント | 使用する IAM 権限 / 宛先エンドポイント / 認証方式 |
| 9 | ログ・メトリクス | 出力するログ項目・メトリクス名 |
| 10 | 性能・上限 | 想定件数・所要時間・上限（Lambda 15 分等）|
| 11 | 未決事項 | ID / 内容 / 確認先 |

## 4. 記載のルール

1. **設計の正は md（10-18 章）**。本 Excel は処理単位に展開した実装・テスト用の器であり、**md と矛盾したら md が勝つ**
2. 各処理シートの「基本情報」「権限・エンドポイント」は md から機械的に転記済み。**空欄になっているのは設計者が埋める箇所**
3. 未決は各シート §11 に書き、`03_処理一覧` の未決列にも反映する
4. 1 処理 = 1 トリガ = 1 結果。分岐が 2 系統以上ある場合は処理を分割する
5. **単体テスト観点は §2/§3/§6 から起こす**（I/O の境界値と例外ケースがそのままテストケースになる）
