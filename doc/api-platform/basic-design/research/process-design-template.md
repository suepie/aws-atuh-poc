## 1. なぜ処理単位に分解するか

10-18 章は**領域ごと**（構成・実行モード・検知・台帳・IAM…）に書かれており、レビューと合意には適するが、**実装・単体テスト・運用手順の起点にはならない**。そこで「1 つのトリガから 1 つの結果までの最小単位」＝**処理**に割り、処理ごとに I/O・手順・例外・権限を確定する。この粒度が WBS の `-d`（設計）成果物と 1:1 対応する。

## 3. 処理分解カタログ（SSOT）

> ⚠ この表を変更したら `tools/process_catalog.py` の `PROCESSES` も同時に更新すること（Excel はそこから生成される）。

### 3.1 処理 ID の付け方（系統）

処理 ID の接頭辞で**「いつ動く処理か」**が分かるようにする。

| 接頭辞 | 系統 | 動くタイミング | 実行主体 |
|---|---|---|---|
| **巡回** | 巡回・対象検索 | 1 時間毎 | 対象検索 Lambda |
| **全量** | 全量確認 | 日次定期 + 手動 | EventBridge Scheduler / 運用者 / 認証実装チェック Lambda |
| **確認** | 認証実装確認（1 アプリ）| **巡回起点・全量起点の両方**（共通）| 認証実装チェック Lambda |
| **通知** | アラート通知 | 検知時 | アラート検知 Lambda / CloudWatch |
| **運用** | 運用・異常系 | 随時（異常時・運用操作）| CloudWatch / 運用者 |
| **連携** | アプリ接点 | デプロイのたび | ベンダー CI |

**この分け方にした理由**: 「巡回 / 全量 / 手動」だけで分類すると、**検査本体（確認系 8 処理）と通知（3 処理）が巡回起点でも全量起点でも同一**であるため、大半が「共通」に落ちて接頭辞が情報を持たなくなる。そこで **①「そのモードでしか動かない処理」を 巡回 / 全量 に分け、② 両方から呼ばれる共通部分を 確認 / 通知 として独立させた**。手動は「全量確認の起動元が人である」ケース（全量-02）と運用操作（運用-03）に限られるため、独立系統にせず `実行契機` 列で表す。

各処理シートと処理一覧には **`実行契機` 列**があり、「巡回（1 時間毎）/ 全量（日次）/ 全量（手動・随時）/ 共通（巡回・全量とも）/ 随時」で個別に判別できる。

## 4. 本書で使う呼称（2026-09-10 確定）

| 呼称 | 実体 | 備考 |
|---|---|---|
| **対象検索 Lambda** | 巡回して変更を検知し、台帳へ登録する Lambda | 旧称: 発見 Lambda |
| **認証実装チェック Lambda** | 実際にリクエストを送って認証実装を確認する Lambda | 変更なし |
| **アラート検知 Lambda** | 判定結果を重要度別の宛先へ振り分ける Lambda | 旧称: Alert Router Lambda |
| **認証構成情報** | アプリが提供する監視メタデータ（monitoring.yaml）と API 仕様（openapi.yaml）| 旧称: 監視資材 |
| **認証構成情報連携バケット** | App アカウント側。アプリがデプロイ時に配置し、中央が読む | `auth-monitoring-artifacts-{accountId}` |
| **認証構成情報配置バケット** | 共通基盤側。台帳（registry/）と API 仕様の複写（openapi/）を保管 | 旧称: Monitoring Registry |

> IAM ロール名・関数名・メトリクス名などの**識別子は英語のまま**（`DiscoveryReadRole` / `alert-router` / `DiscoveryLastSuccess` 等）。呼称変更は文書上の表記のみ。

## 5. 記載のルール

1. **設計の正は md（10-18 章）**。本 Excel は処理単位に展開した実装・テスト用の器であり、**md と矛盾したら md が勝つ**
2. 各処理シートの「基本情報」「権限・エンドポイント」は md から機械的に転記済み。**空欄になっているのは設計者が埋める箇所**
3. 未決は各シート §11 に書き、`03_処理一覧` の未決列にも反映する
4. 1 処理 = 1 トリガ = 1 結果。分岐が 2 系統以上ある場合は処理を分割する
5. **単体テスト観点は §2/§3/§6 から起こす**（I/O の境界値と例外ケースがそのままテストケースになる）
